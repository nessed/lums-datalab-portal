# Next.js security upgrade: 16.4.0 to 16.4.1

Branch `proto/redesign-next-upgrade`, cut from the tip of `proto/redesign-2026-11` before round 2. Date: 2026-11-15.

## Why

Builds of the preview printed that Next.js 16.4.0 "is affected by a known security vulnerability". `npm audit` shows three published advisories against `next` 16.0.0 to 16.4.0, all published 2026-10-22:

| Advisory | Severity | What | Affected | Fixed in |
|---|---|---|---|---|
| GHSA-2464-fhr4-w9xw | critical | Unauthenticated remote code execution in the Image Optimization API when SVG files are used | `>= 16.0.0, <= 16.4.0` (also 10.0.0 to 15.5.27) | 16.4.1 (15.5.28) |
| GHSA-673q-mjm6-r5xr | critical | Unauthenticated remote code execution in `use cache` functions returning typed arrays | `>= 16.0.0, <= 16.4.0` | 16.4.1 |
| GHSA-p3m5-59mp-jv5r (CVE-2026-94482) | high | Denial of service in App Router using Server Actions | `>= 16.0.0, <= 16.4.0` | 16.4.1 (15.5.28) |

The first release that fixes all three is **16.4.1** (a patch release of 16.4, published 2026-10-14). The newest 16.x is 16.4.6; `npm audit` suggests it only because it is the latest, not because 16.4.1 is insufficient: with 16.4.1 installed, `npm audit` no longer lists `next`.

How exposed was this site? It is a static export-style build (all pages prerendered, `next start` serves files), with no `use cache`, no Server Actions, and no `next/image` (grep found none). The advisories therefore most likely did not apply to the code we ship, but the site is deployed on Vercel and the build warning is real, so the fix is cheap and removes the doubt.

## What changed

- `site/package.json`: `next` 16.4.0 to 16.4.1 and `eslint-config-next` 16.4.0 to 16.4.1 (exact pins, as before).
- `site/package-lock.json`: regenerated by `npm install next@16.4.1 eslint-config-next@16.4.1 --save-exact`. The diff is only the `next` package, its platform binaries (`@next/swc-*`, all 16.4.1) and `@next/eslint-plugin-next`.
- React and React DOM stay at 19.3.0. 16.4.1 declares the same peer range (`react ^18.2.0 || ^19.0.0`), so nothing else had to move.
- No source code changed.

## Breaking changes reviewed

The 16.4.1 release notes say only that it "contains security fixes" for the three advisories above. The comparison v16.4.0...v16.4.1 is six commits: a test fix, deploy-test backports, "Improve Server Component transport protocol", "Bump `sharp`" (next/image), a publish-branch change, and the version bump. No API, config or file-convention change.

Checked against the repo anyway:

- `site/next.config.ts` (`turbopack.rules`, `turbopack.root`, `rewrites()`): no new or changed options in a patch release. The build read it without warnings.
- Prerendering with `generateStaticParams` and `dynamicParams = false`: 8,381 static pages generated, same shape as before.
- The "Server Component transport protocol" change touches the React flight payload only; the browser and server are from the same package, so there is no version-skew problem inside one deployment. (Worth knowing for a rolling deploy: an old client page talking to a new server was not tested.)

Load times are not comparable: both runs were on a busy machine.

## Behaviour changes

None observed. Same page count, same checked values, same accessibility result, same JavaScript size. The only visible difference is that the build no longer prints the security notice.
