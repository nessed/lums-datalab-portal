# Run plan (2026-11-23): from "what our pipeline extracted" to "Pakistan's economy in one place"

Requested by Ali on 23 November 2026. Front end only. Branch `proto/hub-2026-11`, draft PR against `main`,
nothing merges to `main` until Ali says so. The agent's prompt is `2026-11-23-data-hub-opus-prompt.md`.

## 1. Why

Ali's verdict on the live site (https://lums-datalab-portal.vercel.app/), reading it as a first-time visitor:

- The home page reads like an index of what our pipeline extracted, not like Pakistan's economy at a glance.
- Too much text on the first screen, and all of it at one volume: six identical cards, each with seven lines.
- The site keeps explaining itself (receipts, checks, "no language model writes a number") instead of showing the
  economy. That text reads as filler.
- Menu and label words mean nothing to a visitor: "Topics", "Sources", "Annual Budget Statement", "BE", "RE",
  "as printed", "core", "corroboration", "No area printed".
- The headline figures should be a side section, not the whole page.
- The documents themselves are invisible. A visitor should be able to open any document in our collection in a
  proper viewer on the site, and download any dataset, without knowing our internal names.

## 2. What the site becomes

One sentence: **the place to see, read and download Pakistan's official economic data.** Three things a visitor can
do, each one click from anywhere:

1. **See** the economy: a home page that leads with one chart, a ticker and a short list of key numbers.
2. **Read** the documents: a Library where every source document opens in an on-site PDF viewer.
3. **Take** the data: every dataset previewed and downloadable from the same Library.

The receipt (every number opens the page it was printed on) stays exactly as it works today. It stops being the
subject of the site and becomes a quiet property of every number.

## 5. Home page (desktop first, 1440 px wide; phones only need to not break)

Top to bottom:

1. **Header**: wordmark, search field, the five links.
2. **Ticker**: one line of key figures moving left (name, value, arrow). Pure CSS. It pauses on hover and on
   keyboard focus, has a visible pause button, and stands still when the visitor has asked for reduced motion.
   Every item is an ordinary receipt-linked value. Without CSS animation it is a plain row that wraps.
3. **Main row**, two thirds and one third:
   - left, **the featured chart**: one trajectory, large, with a one-sentence headline above it and its source
     below. The sentence comes from a story (item 5) and its numbers are computed from the release.
   - right, **Key numbers**: the six headline figures as a slim list. One row each: name, value, arrow, and the
     basis of the change in four words or fewer ("on last year's budget"). No paragraph, no "(how)".
4. **What moved**: two or three compact ranked panels, only where checked data exists. For example: prices by group
   for the latest month, where the latest federal budget goes by function.
5. **Stories**: three or four cards, each one sentence and a small chart, linking to the story page.
6. **Library strip**: the newest documents (kind, year, "Open") and the datasets (name, years covered, "Download").
7. **Explore by theme**: compact tiles.
8. **Footer**: one line on how we check, the release, the links. Smaller than today's.

Hard limits, measured by a script on the built page at 1440 by 900:

- At most 120 words visible on the first screen, not counting the header and ticker.
- One dominant element (the featured chart). No block of running text longer than two lines above the fold.
- At most one sentence anywhere on the page about how the site works.
- Not every value is underlined: links inside data components show their underline on hover and focus. The receipt
  mark stays. Links in running text keep their underline.

## 6. Stories ("X has gone up over the years")

- A story is an entry in `site/editorial/stories.json`: the series, the kind of figure, a sentence pattern, and the
  chart to draw. **No digits in the file.** The existing answer pages become stories; the address stays `/answers`.
- A small fixed set of patterns, each computed by code from the release:
  - latest against the previous comparable figure (same kind);
  - change over N years (same kind at both ends, both checked);
  - ranking inside a group (which price group rose most);
  - share of a total (only where the parts-add-up check passed).
- **Like with like.** A budget estimate is compared only with a budget estimate. Where last year's figure was later
  revised, the story says so in the same sentence or shows the revised figure beside it. This fixes the current
  "health up 17.1%" headline, which hides that the 2025-26 figure was revised far above its budget.
- A story whose figures are not all checked does not render (no number, no sentence). Never a forecast.
- Every derived number in a story or the ticker is recomputed by a new check plug-in (`home-stories.mjs`).

## 7. Library

### 7.1 Documents

- **Index (`/library`)**: every document in the collection as a card or row: plain kind, year, publisher, pages,
  file size, and three actions: **Read** (viewer), **Download** (PDF), **Official page**. Filter by publisher, kind
  and year; a text filter on the title. Grouped by kind by default, newest first.
- **Document page (`/sources/[id]`, kept)**: leads with the viewer and the three actions. Below: what we read from
  it (the series, linked), the pages we read as thumbnails (click jumps the viewer to that page), then the
  provenance facts (fingerprint, archive copy, checks) folded away.
- **Viewer**: pdf.js (`pdfjs-dist`), loaded only on document pages. Page number and total, previous and next, zoom,
  fit to width, text search inside the document, download, full screen. It opens at `#page=N`. It fetches by byte
  range, so a 15 MB report shows its first page before the whole file arrives. Without JavaScript the page shows a
  plain link to the PDF.
- **From any number to the whole document**: the evidence sheet gains "Open the full document at this page", which
  lands in the viewer on that page.
- The release holds 26 sources: 25 PDFs (60.5 MB, 1,566 pages) and one State Bank data file. One labour force file
  failed verification and is not used; it is listed as rejected with the reason, with no viewer.

### 7.2 Datasets

- **Index (`/library/datasets`)**: one card per dataset: plain name, what it measures in one line, years covered,
  number of series, **Preview** (the first rows in an on-page table), **Download** (CSV, Excel), **Open in chart
  builder**. The existing "everything" downloads (`all.csv`, `all.xlsx`, `all.zip`) sit at the top.
- Tables as printed (`/tables/[slug]`) are reached from the document page and the dataset card.

### 7.3 Where the files come from (Ali decides; a default is set so the run is not blocked)

Source PDFs are not in git. For the site to serve them, a new prebuild step (`scripts/prebuild/library.mjs`) fills
`public/data/<version>/sources/` for each manifest row, in this order: the local `SOURCES_DIR` folder; the build
cache; the official address; the Internet Archive copy. Each file must match the `sha256` in the manifest or it is
dropped. A document with no verified file still gets its card and page, with "Official page" only and no viewer.
The build never fails because a government site is down, and never serves a file that does not match.

- **L1, mirroring.** Serving whole government PDFs from our address is a policy call for Ali and the department.
  Default for the preview: mirror, with the publisher, the official link and the fingerprint beside every file.
- **L2, the whole corpus.** The design is driven by a manifest, so adding documents means adding rows and files,
  not code. The wider shared corpus (the Drive folder shared with Ahmad) could not be read when this plan was
  written, so its size is unknown. Above a few hundred MB the files need object storage, which belongs with
  Ahmad's bridge. The front end reads one setting, `LIBRARY_FILES_BASE`, so the files can move without code changes.
- **L3, documents with no extracted data.** They may be listed (kind "document only", viewer and download, no
  series). No number from them appears anywhere, because nothing was read from them.
