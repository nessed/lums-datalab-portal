## 1. What this site is for

A research bank of Pakistan's economic and fiscal data where **every number can be checked**: it links to the exact spot on the government page it came from, it has passed arithmetic checks, and it can be cited permanently. Audiences in order: researchers and economists, journalists, citizens. The site reads frozen release files (`releases/<version>/*.json`, described in `schema/*.schema.json` and `docs/SCHEMA.md`); it never fetches live data and never computes a published number.

The six things a visitor comes to do. Every design decision serves one of them:
1. **Find** a series or a document (search, browse, follow a link someone sent).
2. **Understand** it at a glance: what it measures, unit and scale, which vintage, where the breaks are, where the gaps are and why.
3. **Verify** a number: see the page, the box around the figure, the checks it passed, in plain words.
4. **Take it away**: download with provenance, cite, permalink, use the files programmatically.
5. **Understand the method and the caveats**: coverage vs accuracy, statuses, what is withheld and why, what LLMs did and did not do.
6. **Trust the site itself**: who made it, versioning and errata, licence, a clear "prototype" label.

The flagship page is the **receipt** (`/o/<id>`). If one page has to be perfect, it is that one.

## 3. Design direction, and what to avoid

### Direction
A serious reference work brought online: think a well-set statistical yearbook, Our World in Data's series pages, FRED/ALFRED's handling of vintages, gov.uk's plainness, Tufte's respect for the reader. Specifically:
- **Typography does the work.** One sans for UI and one serif (or a second sans) for long-form at most, loaded with `next/font` (self-hosted, no layout shift). **Tabular numerals wherever a number appears** (`font-variant-numeric: tabular-nums`), right-aligned numeric columns, consistent decimal places per unit, thin-space or comma thousands grouping as the document prints.
- **Dense but legible.** Researchers want tables. Generous line height, hairline rules, no card-with-shadow for every block. White space is for hierarchy, not decoration.
- **A restrained palette:** near-black on off-white, one accent for links and the receipt box, and **exactly one semantic colour system for status** used identically everywhere: checked, disputed, gap (not published by the government), gap (not yet verified by us), withheld. Define it once (section 5) with shapes/patterns as well as colour so it survives greyscale printing and colour-blindness.
- **Charts are drawn, not decorated:** thin lines, direct labels at line ends instead of a legend where possible, break markers as labelled vertical rules, gaps as visible absence (never interpolated), disputed points hollow, hover gives the exact printed value with its vintage and a link to the receipt, axes with sensible ticks and humanised units (Rs million → "Rs 2.4 trillion" on the axis, exact value on hover). Keep the hand-rolled SVG approach (no heavy chart library); use D3's scale/axis/shape modules if it helps. If a `dataviz` skill is available in your session, load it before writing chart code.
- **Page renders look like documents:** a paper-like frame, the cell box drawn in the accent with a thin outline and a slight tint, a magnified crop beside or above the full page, zoom on click, page number and document title always visible, alt text that says what it is.
- **Quiet UI chrome:** text and outline buttons, one primary action per view, no icon soup. Icons only where they carry meaning (download, copy, external link) and always with a label or accessible name.
- **URL is state:** chart toggles, period range, compare selections, search queries live in the URL so links are shareable and the back button works.
- **Mobile is a first-class layout,** not a squeezed desktop: tables become scrollable with a sticky first column or stack sensibly, charts reflow, the receipt keeps the page render usable.
- **Print stylesheet** for receipts and series pages (a researcher will print a receipt).
- Light theme first, done completely. Dark mode only if it costs little and stays consistent; never half-done.

### Avoid (if you catch yourself doing any of these, stop)
- A hero with a gradient, blurred blobs, a stock illustration, or a tagline like "Unlock Pakistan's data".
- Three-up feature cards with icons ("Fast", "Reliable", "Open"), "Trusted by", testimonials, carousels, counters that animate.
- Emoji anywhere. Placeholder or marketing copy. Words like "seamless", "powerful", "cutting-edge", "empower".
- Default Tailwind component looks (indigo-600 buttons, rounded-2xl cards with shadow-lg everywhere, gray-50 page backgrounds with white cards).
- Purple/indigo accents, glassmorphism, neon on dark, oversized rounded corners.
- A legend-only chart with six similar colours; pie charts; 3D anything.
- Hiding caveats in a footer. The prototype label, the "no DOI yet" note, and gap reasons are part of the content, not fine print.
- Inventing anything: numbers, dates, document titles, "last updated" stamps not from `release.json`.
- Shipping a page you have not looked at (section 4).

## 5. Page-by-page acceptance criteria

### Global
- Header: wordmark in text ("LUMS DataLab" + a small "prototype" mark; no logo file until sir's OK), primary nav (Browse, Sources, Methods, Releases, About), search entry point (Ctrl/Cmd-K and a visible field), release version visible.
- A single consistent **prototype notice** (one line, dismissible, repeated in the footer): prototype release, no DOI, not yet for citation in publications; figures compiled from official publications, the printed document prevails.
- Footer: licence (CC BY 4.0 data, MIT code), disclaimer, "Report an error" (prefilled with the current page id, link target from `release.config.json → repoUrl` issues), repository link, release version and build date from `release.json`.
- **Status system** (used identically everywhere, defined in `StatusLegend`):
  - `checked` — solid mark, calm colour; on hover/expand: tier A or B in words ("verified by a sum and a second printing" / "verified by a sum").
  - `disputed` — hollow/amber mark; "two official printings disagree; both shown on the receipt".
  - `gap: not published by the government` — hatched grey cell.
  - `gap: not yet verified by us` — dotted grey cell.
  - `withheld` (failed checks) — grey with a short reason.
  - Unknown value from a newer release → raw label in neutral style, never a crash.
- Every page: breadcrumbs, a cite action where there is something citable, download where there is data, permalink copy.

### Receipt `/o/[id]` (flagship)
- Above the fold: the figure large with unit, scale and vintage in words ("Rs 31,975 million · budget estimate · 2025-26"), the series name as a link, the status with its one-sentence meaning, and the **magnified crop** of the cell with the box.
- The **page render** with the box, zoomable, with document title, page N of M, and a "what you are looking at" caption; a link to the official URL and the Wayback snapshot (both from the source record), with the verification status of the file in words.
- **The checks it took part in**, each as a sentence and, expandable, the arithmetic: the members with their values (each a link to its own receipt), the printed total, the residual, the tolerance rule in words. Cross-edition: the other printing with its document and page. Disputed: every printing listed, none presented as the answer.
- **Provenance block:** document, page, table, row/column labels as printed, run id, extractor and version, document SHA-256 (truncated with copy), release version, first published in.
- **Caveats block** from the observation/series notes (for example "current expenditure on revenue account only"; the devolution break; "no actuals in this source").
- **Actions:** copy citation (APA, BibTeX, RIS; two-part: original document + portal release), copy permalink, download JSON receipt, download CSV row with provenance columns.
- Neighbours: previous/next period of the same series, the parent series, siblings.
- Print layout: figure, crop, checks, provenance on one or two pages, no chrome.

### Series `/series/[id]`
- Title, definition (with its `draft` mark if so), unit/scale, frequency, dims, breaks listed with their notes, parent/children/siblings, synonyms (for search), source document types.
- **Chart:** one line per vintage (BE and RE distinct and labelled at line end), break rules with labels, gaps visible, disputed hollow, hover with exact value + vintage + period + a link to the receipt; toggles in the URL: nominal / share of total (if the derived series exists) / log scale / period range; for index series, base-year segments never joined.
- **Table:** every observation: period, vintage, value (tabular), status, source document + page → receipt link; gaps as rows with their reason; sortable by period; sticky header; mobile-friendly.
- Actions: CSV (with provenance columns: obs_id, source_id, page, cell_id, status, release), JSON, cite the series, permalink, "add to compare".

### Browse `/browse` and search
- A real catalogue: dataset → hierarchy tree (functions → sub-functions; CPI areas → groups; LFS measures → sex/area/province), with counts and a sparkline + latest value per series; filters (dataset, period range, status mix, vintage); document view (by source edition → which series it contributes).
- Search: prebuilt JSON index over series ids, names, synonyms, document titles; instant results as you type; keyboard navigable; results show dataset, unit and latest period; Ctrl/Cmd-K opens it anywhere.

### Home `/`
- One sentence of what this is; the **live numbers** from `release.json` as a plain stat row (values published, documents, checks run, coverage, check pass rate, measured error rate "pending gold set"), each linking to methods.
- The datasets as a compact table (dataset, editions/periods covered, published values, status: published / coming with reason).
- "Start here": the featured series (federal health spending, with the devolution break visible), the featured receipt ("see how one number is verified"), the demo.
- Latest release and changelog line; the prototype notice. No hero, no feature cards.

### Sources `/sources`, `/sources/[id]`
- List: document, period, role (core / corroboration / cross-source), verification status in words with a plain explanation of each status, pages used, coverage per table as a thin bar with the number, run id.
- Detail: the verification record rendered readably (what was checked, official URL, Wayback, hashes, inspection results, any caveat), pages used with thumbnails linking to receipts on that page, tables located with coverage, the Docling run details.

### Methods `/methods`
- Rendered from `docs/METHODS.md` with the live numbers substituted; a drawn (SVG, themed) pipeline diagram; the status definitions; thresholds table from the release; what LLMs did and did not do; known limitations; how to reproduce (link to `HOW_TO_REPRODUCE.md`). A table of contents; readable measure (65–75 characters).

### Demo `/demo/health-and-jobs`
- A narrative with charts; **every figure in the text is a link to its receipt**; the devolution break explained in one sentence; the caveat that the health line is current expenditure only (or total, if the pipeline agent lands it) stated where the chart is.

### Compare `/compare?s=a,b,c`
- Up to three series on one chart (shared period axis; separate value axes only if units differ, said plainly), the same table and download pattern, shareable URL.

### Releases `/releases`, About `/about`, Data access `/data`
- Releases: version, date, scope, counts, changelog, errata, "no DOI yet", how versions and citations work.
- About: who (DataLab at LUMS Department of Economics, the two RAs by role), licence, disclaimer, contact/report path, the repository.
- Data access: the file layout of a release (`observations.csv/.json/.parquet`, `cells`, `checks`, `sources`, `series`), column meanings, a Python and an R snippet to load the CSV, the permalink and JSON receipt pattern, the citation rules.
